# Synthetic evaluation corpus

This corpus contains 80 harmless static MCP tool definitions: 40 benign and 40 suspicious. Its manifest explicitly declares the `development` split because the examples have been visible during detector development and tuning. It is designed for deterministic regression experiments, including deliberately ambiguous security, administration, privacy, quotation, and encoded-fixture language. It contains no real secrets, operational exploit payloads, destructive commands, network dependency, or executable content.

`manifest.json` is the ground truth. Corpus-level metadata records the split, methodology version/note, label-review status, and source/license policy. Every entry selects one tool from a small catalog and supports a unique ID, source type, binary label, expected detector categories, rationale, normalized difficulty, provenance, optional expected stable rule IDs, optional expected field locations, and researcher notes. Omitted provenance defaults to `synthetic`. Legacy `easy` and `borderline` difficulty values normalize to `obvious` and `moderate` for backward compatibility. The evaluator validates paths, labels, categories, strict field locations, duplicate IDs, and selected tool names before scanning.

The corpus is synthetic and single-reviewer labeled. Results measure behavior on these development examples only and are not holdout results or evidence of real-world attack-detection accuracy. A separate 48-sample holdout exists under `evaluation/holdout/`; its first confirmatory evaluation is complete and it is now exposed. Changes to examples, labels, or other research-significant manifest data require a corpus version change and an entry in `evaluation/CHANGELOG.md`. See `docs/research-protocol.md` for split isolation, preserved evidence, and post-unblinding policy.
